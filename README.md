# NVM

A virtual machine with its own instruction set architecture (ISA), a C interpreter and a Python assembler.

## Layout

```
nvm                        interpreter (compiled)
src/core/bytecode_interpreter.c   interpreter and bytecode loader
src/cpu/cpu.h              CPU architecture: registers, memory, instructions
src/cpu/dump.c             register/memory/stack dump
src/asm/nvmasm.py          assembler
nvmasm                     launcher script for the assembler
```

## Building

Requires a C compiler (gcc/clang) and Python 3.

```sh
gcc -o nvm src/core/bytecode_interpreter.c
```

## Quick start

```sh
./nvmasm test.asm test.bin   # assemble bytecode
./nvm test.bin               # run it
```

## Assembler

```sh
./nvmasm <input.asm> <output.bin> [options]

  -d, --debug    show tokens, IR, labels, macros and generated bytecode
  -nh, --no-header  do not emit the 8-byte header
```

### Directives

| Directive    | Description                                      |
| ------------ | ------------------------------------------------ |
| `signature`  | file signature (usually `NVMB`)                  |
| `loc`        | load address in memory (usually `0x2000`)        |
| `entry`      | entry point — a label                            |
| `reserve N`  | reserve N zero bytes                             |
| `bytes`      | emit bytes / a string                            |
| `words`      | emit 16-bit values / a string                    |
| `dwords`     | emit 32-bit values                               |

### Preprocessor

```asm
#include "file.asm"

#const answer 42

#macro print msg {
    mov d0 msg
    vmcall 0x12
}
```

### Labels

- `main:` — normal
- `.loop:` — local (belongs to the current parent label)
- `~msg:` — relative (address = position + load address)
- `data@0x1000:` — pinned to a specific address

### Literals and registers

- numbers: `42`, `0x2A`, characters `'A'`, strings `"text"`
- registers: `d0`–`d7` (32-bit), `w0`–`w7` (16-bit), `b0`–`b7` (8-bit), `sp`
- pointer dereference: `*` before an operand, e.g. `mov d0 *d1`, `mov d0 *10`

### Instructions

Arithmetic: `add, sub, mul, div, inc, dec`
Logic: `and, or, xor, not`
Memory: `str, ldr, strb, ldrb, strs, ldrs, ldapc, ldab`
Stack: `push, pop, pushf, popf`
Branches: `jmp, je, jne, jl, jg, jle, jge` (flags are set by `cmp`)
Other: `mov, cmp, call, ret, nop, vmcall`

### System calls (vmcall)

The call number is passed as an operand, arguments via registers `d0`–`d3`.

| Code | Name    | Arguments                          | Description                |
| ---- | ------- | ---------------------------------- | -------------------------- |
| 0x10 | `PUTC`  | `d0`                               | print a character          |
| 0x11 | `GETC`  | `d0`                               | read a character           |
| 0x12 | `WRITE` | `d0` (address)                     | print a string (until NUL) |
| 0x20 | `MEMCPY`| `d0` dest, `d1` src, `d2` size     | copy memory                |
| 0x21 | `MEMSET`| `d0` dest, `d1` val, `d2` size     | fill memory                |
| 0xFD | `TRAP`  | —                                  | interactive debugger       |
| 0xFE | `DUMP`  | —                                  | dump VM state              |
| 0xFF | `EXIT`  | `d0` (exit code)                   | terminate the VM           |

## Bytecode format

Header (8 bytes):

```
NVMB | location (2 bytes BE) | entry point (2 bytes BE)
```

The processor loads at address 0x2000; the entry point is relative to the load address.

An instruction is: `opcode sign data sign2 data2 ...`

Operand signatures:

| Signature | Operand                       |
| --------- | ----------------------------- |
| `F0`      | register (1 byte, index)      |
| `F1`      | number (4 bytes, big-endian)  |
| `F2`      | pointer (next operand)        |

## Architecture

- 24 general-purpose registers: `d0`–`d7`, `w0`–`w7`, `b0`–`b7` — independent
- Special: `sp`, `pc`; flags: `zf, sf, cf, of`
- 64 KB of data memory + 64 KB of stack; each byte is a value plus access permissions
- Memory size is controlled by the `MEMORY_MAX` constant in `src/cpu/cpu.h`

## Debugging

- `vmcall 0xFE` — dump registers, memory and stack
- `vmcall 0xFD` — interactive trap: `r` (registers), `m` (memory), `s` (stack), `a` (around PC), `ct` (continue), `q` (quit)
- `./nvmasm -d file.asm out.bin` — detailed assembly breakdown
